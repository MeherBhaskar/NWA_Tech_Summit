The sharpest public disagreement in agentic engineering, staged side by side.
Anthropic (Jun 2025): orchestrator-worker beat single-agent Opus by 90.2% on their research eval; parallel tool calls cut research time up to 90%; works because subtasks are READ-ONLY, findings return compressed.
Cognition (Jun 2025, Walden Yan): "Don't Build Multi-Agents" — share full context; actions carry implicit decisions; parallel writers make conflicting decisions that compound. Claude Code sub-agents work because read-only; otherwise single-threaded + compaction.
Shared ground: token usage explained 80% of performance variance; multi-agent ≈ 15× chat tokens; LangChain's deep-agents = pragmatic middle; everyone says start simple.
Land the decision rule: fan out only for read-only or independently verifiable breadth; write paths stay single-threaded with full context.

Second half of context engineering: what happens when the window fills anyway. Four moves, each with provenance:
(1) COMPACTION — summarize old turns, regenerate state from artifacts (Manus rebuilds from todo.md; standard in Claude Code).
(2) STRUCTURED NOTES — persist findings outside the window (NOTES.md pattern; Anthropic's effective-context-engineering post).
(3) RECITATION — rewrite the objective into recent context every few turns; fights lost-in-the-middle; Manus credits it for coherence across ~50-tool-call tasks.
(4) SUBAGENT QUARANTINE — fresh-context worker reads the haystack, returns only the answer (LangChain deep agents; Claude Code read-only pattern).
Honest framing: practitioner heuristics, not papers — but they're what's shipping in production today.
Day-one move: context-budget check per turn — tokens-in trending up turn-over-turn is your earliest drift/loop/cost warning.
Time: 4–5 min.

The compounding math, as a static curve with sampled points. P = rN: at 95% per step, a 10-step agent succeeds end-to-end only ~60% of the time. Sampled points to call out:
· r=0.99, N=10 → 90% · r=0.95, N=10 → 60% · r=0.90, N=10 → 35%
· same r=0.95 but N=20 → 36%. Depth hurts as much as per-step quality.
Then the engineering: retries (r′=1−(1−r)²), fallbacks, breakers, timeouts buy back the exponent — engineered bar lands ≥97% before human-facing autonomy.
Be honest about assumptions: retries assume independent failures (cap + jitter them); fallback needs a safe partial answer; mutating steps need idempotency keys or retry = double-delete (Replit tie-in).
Name the 90–97% dead zone explicitly — most teams live there for months; partial autonomy with sampled review is the honest answer.
Ask: "What's your longest agent chain in prod today? What's its per-step rate?"
Time: 5 min.
Cut from slide: retry formula r′ = 1−(1−r)². Fine print: retries assume independent failures (cap and jitter them); fallbacks assume a safe partial answer; without idempotency keys, a retry IS a double-delete. Thresholds are practitioner heuristics — set sample rate by blast radius.

Prompting alone doesn’t fix loops.  Gates that fail closed do.

Frame with Anthropic's numbers first: multi-agent research used ~15× the tokens of chat; token usage ALONE explained 80% of performance variance across their evals. So tokens are simultaneously your quality dial and your bill — governance decides which one you're turning.
Three levers, in ROI order: (1) ROUTE — most traffic doesn't need your biggest model; blended savings of ~60–80% are a widely-repeated practitioner rule-of-thumb, NOT a sourced benchmark — present it as directional, invite skepticism. (2) CACHE & REUSE — KV/prefix caching first (Manus measured ~10× on input price), then semantic response caches. (3) GOVERN — per-principal quotas, per-run budget caps enforced by the orchestrator, batch queues for offline work, runaway-loop kill switches (Replit's emergency off-switch exists BECAUSE of the incident).
Ask: "Who owns inference cost in your org today?" If you can't name an owner, that's the finding.
Day-one move: every agent feature ships with cost-per-completed-task, reviewed like an SLO.

Key reframe: you cannot unit-test creativity — so test the CONTRACT, not the prose. Deterministic assertions on structure; judge models on quality; humans on taste.
The pyramid matters: teams over-invest at the top (vibes) and under-invest at the bottom (deterministic gates).
CI integration explicitly: eval suite runs on every PR touching prompts, tools, or models; score drop beyond threshold = blocked merge. That's the whole discipline.
Honest caveat on judges: LLM-as-judge correlates well with humans once CALIBRATED against human labels — but judges have known biases (verbosity, self-preference). Calibrate before trusting.
Tie-back: the MIT 95% stat is largely an eval-discipline stat — pilots that couldn't demonstrate value were usually pilots that never measured it.
Time: 4 min.
Engineering angle: treat the eval suite like any test suite — size the golden set for the effect you need to detect; report deltas with confidence intervals; check judge-vs-human agreement (e.g., Cohen's kappa) before trusting a judge.
