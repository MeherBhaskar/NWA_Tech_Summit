02 · Orchestration

Delegation patterns — matched to task shape

SUPERVISOR · dynamic decomposition
Fails: bottleneck, context bloat, one bad plan misdirects the fleet. Fix: hard turn/token budgets · compressed returns.

PIPELINE · known DAG — most production value lives here
Fails: drift poisons downstream stages; retries replay the chain. Fix: typed contracts · retry-from-checkpoint · dead-letter queue.

BLACKBOARD · parallel read-only research
Fails: write races, duplicated work, no completion signal. Fix: additive versioned writes · leases · explicit quorum.

DEBATE · verification by contention
Fails: sycophancy collapse; 3× cost, 2× latency per decision. Fix: adversarial roles · capped rounds · human escalation.

Delegation contract: deadline + token budget on every delegation · structured summaries back · mutating steps never fan out · one owner of the final answer.

The rules that protect the cache

  1. ①  one stable top-of-prompt block: system · tools · docs
  2. ②  volatile data (timestamps! session ids!) at the tail, never the head
  3. ③  append-only history — edits invalidate everything after them
  4. ④  mask unavailable tools via logits; removal breaks the prefix

Why engineers care: cached tokens bill at $0.30 vs $3 per MTok — a ~10× price gap — and serve faster, so the same discipline cuts p50 latency. Cache-aware structure is day-one design, not an optimization pass. (Manus, Jul 2025)

Day-one move

Put cache-hit rate on your dashboard next to error rate. A falling hit rate is the earliest signal of prompt drift — and of money burning quietly.

Second half of context engineering: what happens when the window fills anyway. Four moves, each with provenance:
(1) COMPACTION — summarize old turns, regenerate state from artifacts (Manus rebuilds from todo.md; standard in Claude Code).
(2) STRUCTURED NOTES — persist findings outside the window (NOTES.md pattern; Anthropic's effective-context-engineering post).
(3) RECITATION — rewrite the objective into recent context every few turns; fights lost-in-the-middle; Manus credits it for coherence across ~50-tool-call tasks.
(4) SUBAGENT QUARANTINE — fresh-context worker reads the haystack, returns only the answer (LangChain deep agents; Claude Code read-only pattern).
Honest framing: practitioner heuristics, not papers — but they're what's shipping in production today.
Day-one move: context-budget check per turn — tokens-in trending up turn-over-turn is your earliest drift/loop/cost warning.

03 · Context Engineering

When the window fills: four field-tested moves

Long-horizon agents die of context rot long before they die of model limits. Attention is a finite budget — spend it deliberately.

MOVE 1 · Compact

Compress, don't truncate

When history grows past budget, summarize old turns and regenerate state from artifacts — naive truncation loses constraints mid-task.

In practice

drop oldest turns → keep todo + key facts → rebuild working state from files

MOVE 2 · Note-take

Memory outside the window

Agents persist findings to structured notes (NOTES.md pattern): environment feedback, milestones, failures to avoid — re-readable regardless of conversation length.

In practice

write-once-per-milestone · notes survive compaction · failures kept deliberately

MOVE 3 · Recite

Keep the goal on top

Re-write the objective (todo.md) into recent context every few turns. Recitation fights lost-in-the-middle: Manus credits it for coherence across ~50-tool-call tasks.

In practice

todo.md rewritten after milestones → goal stays near attention peak

MOVE 4 · Quarantine

Subagents as airlocks

For haystack searches, spawn a fresh-context subagent that reads everything and returns only the conclusion. Main thread pays for the answer, not the reading.

In practice

read-only workers · compressed findings back · main context stays clean

⚑

Day-one move: add a context-budget check to your agent loop — tokens-in-per-turn trending up turn-over-turn is your earliest warning of drift, loops, and runaway cost. One number, catches three failure families.

The compounding math, as a static curve with sampled points. P = rN: at 95% per step, a 10-step agent succeeds end-to-end only ~60% of the time. Sampled points to call out:
· r=0.99, N=10 → 90% · r=0.95, N=10 → 60% · r=0.90, N=10 → 35%
· same r=0.95 but N=20 → 36%. Depth hurts as much as per-step quality.
Then the engineering: retries (r′=1−(1−r)²), fallbacks, breakers, timeouts buy back the exponent — engineered bar lands ≥97% before human-facing autonomy.
Be honest about assumptions: retries assume independent failures (cap + jitter them); fallback needs a safe partial answer; mutating steps need idempotency keys or retry = double-delete (Replit tie-in).
Name the 90–97% dead zone explicitly — most teams live there for months; partial autonomy with sampled review is the honest answer.
Ask: "What's your longest agent chain in prod today? What's its per-step rate?"

04 · Reliability

Reliability compounds — and decays

End-to-end success of an N-step chain at per-step reliability r is simply P = rᴺ. The exponent is what kills pilots.

90%

r=0.99 · N=10

60%

r=0.95 · N=10

35%

r=0.90 · N=10

Buy the exponent back

  1. ①  retry w/ backoff+jitter  r′ = 1−(1−r)²
  2. ②  fallback / degraded path on hard failure
  3. ③  circuit breaker + timeout everywhere
  4. ④  idempotency keys on anything that mutates

Honest fine print

Retries assume independent failures — cap and jitter them. Fallbacks assume a safe partial answer exists. On mutating steps without idempotency keys, a retry IS a double-delete.

Practitioner heuristics — calibrate on your workload, not gospel. The dead zone is where real teams live: ≥97% earns autonomy · ≤90% keeps a reviewer on every run · 90–97% = partial autonomy with sampled review — set the sample rate by blast radius, tighten after every incident.

Honest framing: illustrative model trajectories, not benchmark data — the SHAPE is the finding.
Production lesson: loops aren't fixed by better prompting alone; they're fixed structurally, with gates that fail closed. Also keep failures IN context deliberately (Manus) so the agent doesn't repeat them.

04 · Reliability

Hallucination loops: watching drift happen

The loop, formally

  1. ①  small factual error in output
  2. ②  plan built on the error
  3. ③  tool results read as confirmation
  4. ④  confidence ↑ · divergence compounds

Break it structurally

  • · Grounding gate — claims must cite context; fails closed
  • · Validation — schema + sanity checks on tool outputs
  • · Reflection — critic pass; catches late drift, costs latency
  • · Keep failures in context — don't launder them out

Replit was this loop: failing tests → fabricated users → kept building on the lie. Structural gates would have failed closed at step ①. Prompting alone wouldn't have.

Trajectories are illustrative model runs, not benchmark data — the shape is the finding.

Frame with Anthropic's numbers first: multi-agent research used ~15× the tokens of chat; token usage ALONE explained 80% of performance variance across their evals. So tokens are simultaneously your quality dial and your bill — governance decides which one you're turning.
Three levers, in ROI order: (1) ROUTE — most traffic doesn't need your biggest model; blended savings of ~60–80% are a widely-repeated practitioner rule-of-thumb, NOT a sourced benchmark — present it as directional, invite skepticism. (2) CACHE & REUSE — KV/prefix caching first (Manus measured ~10× on input price), then semantic response caches. (3) GOVERN — per-principal quotas, per-run budget caps enforced by the orchestrator, batch queues for offline work, runaway-loop kill switches (Replit's emergency off-switch exists BECAUSE of the incident).
Ask: "Who owns inference cost in your org today?" Silence is the finding.
Day-one move: every agent feature ships with cost-per-completed-task, reviewed like an SLO.

05 · Cost & Compute

Tokens are your quality dial AND your burn rate

Lever 1 · Route

Not every token deserves a frontier model

A small classifier routes by complexity: extraction and formatting to fast models; planning and synthesis escalate to frontier ones. Practitioners commonly report blended savings of roughly 60–80% at equal task quality — treat it as directional until you measure your own mix — and routing decisions belong in config, not code, so they can be tuned against evals.

Watch for

misroute rate · escalation latency · fallback chain depth

Lever 2 · Cache & reuse

Stop paying twice for the same thought

Prefix/KV caching first (it's free discipline — Manus measured ~10× on input price), then semantic response caches for repeated intents, shared retrieval indices. In multi-turn agents you're paying for the same system prompt thousands of times.

Watch for

hit rate · staleness window · near-duplicate threshold

Lever 3 · Govern

Inference is a shared, finite resource

Per-team quotas, per-run budget caps enforced by the orchestrator, admission control under load, batch windows for offline work. Without governance, one runaway agent loop can consume a fleet budget overnight — the kill switch is load-bearing infrastructure.

Watch for

token burn rate · queue fairness · runaway-loop kill switches

⚑

Capacity is a product decision: every agent feature ships with a cost model — expected turns × tokens/turn × $/token × traffic × cache-hit-rate — reviewed like any other SLO. Anthropic's effort-scaling rules (simple tasks: single agent, few calls; complex: many subagents) are exactly this dial, written down.

Eight things to do before you scale

1

Name two numbers before scaling: end-to-end task success rate and cost per completed task. No numbers, no system — just a demo.

2

Pick orchestration by task shape, not fashion — fan out for read-only breadth; keep write paths single-threaded with full context.

3

Give every delegation a contract: deadline, token budget, structured summary back. Workers compress; only the owner synthesizes.

4

Engineer for cache hits from day one: stable prefix, append-only history, mask-don't-remove tools. It's ~10× on input price and faster p50s.

5

Assume rN decay: retries with backoff+jitter, fallbacks, breakers, timeouts everywhere — and idempotency keys on anything that mutates state.

6

Break hallucination loops structurally: grounding gates and validation that fail closed — not vibes-based prompting.

7

Ship behind gates: tiered evals in CI, shadow mode, canary ramps, automated rollback wired to guardrails. Version prompts like code.

8

Own the evaluation function: decide deliberately what your system optimizes — cost, quality, escalation — or it will optimize whatever you forgot to measure.
